# 启动器插件触发词实施计划

按任务顺序在当前工作区执行 Superpowers 的实施计划流程，用勾选框记录进度。

**目标**　在启动器中按插件声明的触发词搜索，按文本内容推荐插件，并将原文传给用户选中的处理程序。

**实现**　插件注册表统一排序。启动器持有搜索文本、粘贴原文和当前内容的识别结果，后台仅执行插件的纯识别函数。使用现有 Rust、GPUI Kit 和 JSON 校验器。[已确认的设计](../specs/2026-11-18-plugin-triggers-design.md)

## 约束与复核重点

- 开发者声明五个词。检查大小写、首尾空白和插件间的冲突。
- 插件名称允许部分匹配。交换注册顺序后，完整 JSON 仍应优先于通用翻译。
- 检查空白、BOM、JSON 单值和重复键。原文应完整送入用户选择的插件。
- 多行或超过 4 KiB 的粘贴沿用内容标签。筛选和清除筛选时复用同一份识别结果。
- 快速确认、连续替换内容以及关闭后重开窗口时，确认动作只作用于当前输入和窗口。

## 一、插件契约和排序

- [x] 在 `crates/rtools/tests/plugin_registry.rs` 用真实插件验证触发词、输入来源、排序和声明唯一性。先运行 `cargo test -p rtools --test plugin_registry` 复现旧行为。
- [x] 在 `crates/rtools/src/plugin/` 扩展 `PluginManifest.triggers`、内容识别级别和注册表搜索。收集一次内容匹配，再按完整触发词、已识别内容、名称匹配、格式线索和通用文本排序。每个插件只生成一行。
- [x] 在 `plugins/mod.rs` 复用实际内置插件清单，更新 `main.rs` 和四个插件的声明。用 JSON 校验器区分完整值与修复候选。复跑注册表、翻译、语言和 JSON 识别测试。

## 二、输入、粘贴和确认

- [x] 在 `crates/rtools/src/launcher/` 接入缓存的内容匹配。短输入同步识别，长文本使用后台任务，与查询词独立的原文由内容标签持有。只在当前版本上应用结果。
- [x] 让回车和点击使用相同的启动参数。覆盖筛选后回车、识别中回车、替换内容、清除标签和关闭重开。更新 `locales/app.yml` 的筛选提示和 JSON 修复提示。
- [x] 在离屏启动器中用可记录启动参数的插件核对实际事件，验证筛选词不会覆盖正文。将常用触发词与粘贴操作写入 README。

## 三、集成验证

- [x] 运行格式检查、全目标 Clippy 和工作区测试。与现有 IPC 基线核对失败项。
- [x] 构建本地 macOS 应用包并校验签名，供桌面试用。

## 验证结果

- 22 个 macOS 离屏交互用例通过，覆盖键盘、点击、筛选和窗口重开。通过 JSON 编辑器的复制操作核对了缩进列表、仅用回车换行的映射和保留尾部空行的块字符串。暂停首份文档的解析后连续粘贴，确认只处理首尾两份，切回短触发词也能立即打开对应插件。
- 工作区通过 176 项测试。默认忽略的 4 项 macOS 私有粘贴板测试另行执行，全部通过。单实例通信的 `a_live_instance_keeps_its_socket` 和 `server_round_trip` 与改动前的基线一样失败。
- 格式检查、全目标 Clippy 和 Release 构建通过。`target/release/rtools.app` 的本地签名通过校验，包内可执行文件与本次构建的 UUID 一致。
