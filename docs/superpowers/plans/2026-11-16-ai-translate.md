# AI 翻译插件实施计划

## 目标与依据

实现用户已批准的 [中文设计](../specs/2026-11-16-ai-translate-design.md)：中英互译、通用与技术场景、DeepSeek 流式响应、独立设置页、平台安全凭据存储。

在当前工作目录实施，不创建 worktree、commit 或 push。前端按项目规则免单元测试；协议、边界校验和请求状态用测试验证。所有新增函数和复杂逻辑使用英文注释，日志不得包含密钥、原文或译文。

## 结构与接口

- `plugins/translate/core.rs`：`TranslateSettings`、方向与场景、合法 endpoint、请求快照和安全错误；`session.rs` 负责会话版本状态。
- `rig-core` 负责 Chat Completions 编码、SSE 解码和完成原因；应用不维护自定义协议解析器。
- `plugins/translate/client.rs`：使用 rig-core 的 DeepSeek wire 和 rig-reqwest 共享传输，利用其执行器适配；禁用重定向、设置超时，合并增量再通知 UI。
- `plugins/translate/credentials.rs`：GPUI 平台凭据接口，按规范化 endpoint 隔离；保存值优先，其次进程环境变量。
- `plugins/translate/view.rs`：输入与只读输出、可拖动上下分区、任务所有权、快捷键、过期结果标识。
- `settings/translate.rs`：连接草稿、保存连接、密钥来源与保存/移除、固定短文本连接测试；`SettingsWindow` 与 `Shell` 增加定向打开设置页的接口。
- 根 Cargo 工作区统一声明依赖；插件注册、本地化、设置兼容性测试和 README 同步修改。

## 审查重点

密钥隔离与日志脱敏；Task 取消是否释放网络请求；SSE 结束语义；结果与当前输入是否一致；隐藏/分离不捕获旧 Window；避免逐 token 全文复制；所有设置能从插件直接抵达。
