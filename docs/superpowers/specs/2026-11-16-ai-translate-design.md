# AI 翻译插件：需求调研与 UI/UX 提案

日期：2026-11-16。状态：用户已批准，进入产品实现。

## 1. 已确认的需求

- 作为 rtools 的内置插件使用，目前只支持中文与英文互译。
- 内容包括技术文档和日常内容。
- 模型服务只需支持 DeepSeek，不建设多供应商平台。
- 支持读取 `DEEPSEEK_API_KEY`，也允许用户在应用内配置 Key。
- 允许自定义请求 endpoint 和模型名称，默认使用 DeepSeek 官方配置。

用户已批准本提案，包括以下翻译方向判断、布局、场景、凭据优先级和长度限制。

## 2. 调研结论与现有能力

### 官方接口

当前官方入门文档使用 `deepseek-flash`，OpenAI 格式的请求地址为 `https://api.deepseek.com/chat/completions`。模型名不能沿用旧经验硬编码；用户始终可以修改。[官方入门文档](https://api-docs.deepseek.com/)

DeepSeek 当前默认开启思考模式，支持通过 `thinking: { type: "disabled" }` 关闭。本插件的官方默认连接建议关闭思考，直接输出译文；这是减少等待的产品选择，尚未做真实延迟或质量对比。[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)

Chat Completions 支持 SSE 流式增量；接收 `choices[].delta.content`，识别结束标记及 `finish_reason`，将截断与正常完成分开处理。[Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)

不把价格写入界面或硬编码成本估算。官方按 token 计费，价格和模型会变化。[Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/)

### 项目可复用部分

| 现有实现 | 本插件的使用方式 |
| --- | --- |
| `PluginManifest`、`Plugin::accepts`、`Launch.input` | 关键词打开，或选择粘贴内容的翻译入口 |
| `Launcher.views` | 隐藏启动器后保留本次会话及正在进行的翻译 |
| `Shell::detach` | 复用分离窗口，不另建翻译窗口管理器 |
| `SettingsStore`、设置侧栏、`Choice` | 新增「AI 翻译」设置页；配置改变不会重建无关主题 |
| `Toolbar`、GPUI `Textarea`、`Input`、`Select`、`Button` | 复用输入、选择、焦点、工具栏和反馈行为 |
| GPUI `read_credentials` / `write_credentials` / `delete_credentials` | 复用平台凭据存储；macOS 实现使用 Keychain |
| 当前主题和中英本地化 | 全部界面跟随既有外观、字体缩放和语言设置 |

当前 `application()` 没有注入可用 HTTP 客户端，GPUI 默认是 `NullHttpClient`。实现时必须补上真实异步 HTTP 连接，不能仅调用 `cx.http_client()` 就认为具备联网能力。按用户后续指定使用 `rig-core` 的 DeepSeek wire 与 `rig-reqwest`，由库负责协议和流解析；不引入 Agent 工作流。

源码依据：[插件协议](../../../crates/rtools/src/plugin/mod.rs)、[启动器生命周期](../../../crates/rtools/src/launcher/mod.rs)、[设置窗口](../../../crates/rtools/src/settings/window.rs)、[共享工具栏](../../../crates/rtools/src/ui/toolbar.rs)。GPUI 能力核对基于本机安装的 `gpui-kit 0.9.1` / `gpui-pre 0.3.12` 源码。

## 3. 首版范围与方案取舍

首版完成：输入文本、选择方向与场景、发起翻译、查看流式译文、停止、重试、复制译文，以及配置和检查连接。

本期不加入 OCR、文件上传、网页抓取、划词监听、语音、聊天记录、术语库、多模型对比或提示词编辑器。技术文档指直接输入或粘贴的文本 / Markdown，不包括 PDF、Word 排版还原。

| 方案 | 优点 | 代价 | 建议 |
| --- | --- | --- | --- |
| 上原文、下译文 | 在启动器宽度内保持完整行宽，短文本和技术段落都易读 | 长文逐段对照需要分别滚动 | 首版采用 |
| 左原文、右译文 | 宽窗口逐段对照方便 | 约 800 px 的窗口内，每侧窄且频繁换行 | 后续确有长文对照需求再加 |
| 对话式翻译 | 适合多轮讨论措辞 | 原文与对应译文分散，多出会话管理 | 当前任务不需要 |

上下分区在启动器和分离窗口中保持一致，不因窗口略微变化突然切换布局。使用可调整的上下分隔；默认原文约占正文 40%，译文约占 60%。

## 4. 用户流程

1. 双击 Ctrl 唤出 rtools，搜索「翻译 / translate / fanyi」，或粘贴文本后选择「AI 翻译」。
2. 插件填入文本，显示当前翻译方向和场景。关键词打开复用现有会话，内容匹配打开接收新的原文。
3. 用户检查或修改方向，在原文框按 `Enter` 或点击「翻译」；`Shift Enter` 换行，保留 `⌘ Enter` / `Ctrl Enter` 作为附加快捷键。
4. 译文逐步出现；操作按钮变为「停止」。完成后可选择文本，或点击「复制译文」。
5. 若未配置 Key，保留原文，在译文区域显示说明和「配置 DeepSeek…」按钮，直接打开对应设置页。

搜索、粘贴、打开插件、修改方向和切换场景都不自动发出付费请求。只有明确的「翻译」「重试」和「测试连接」操作会联网。

### 启动器匹配

- 增加固定的翻译插件，不改写 JSON / Diff 的识别结果。
- `accepts` 仅做本地、低成本的文本检查；不读取 Key、不联网、不持久化原文。
- 在现有插件之后注册，普通非空文本提供「翻译这段文本」结果；关键词命中仍遵循当前排序规则。
- 不把模型语言识别加入启动器搜索，不因每次键入触发后台请求。

## 5. 主界面

```text
┌──────────────────────────────────────────────────────────────┐
│ ←  AI 翻译                                      分离窗口     │  既有插件标题栏
├──────────────────────────────────────────────────────────────┤
│ [自动检测 ▾]                                   字符数  [×] │
│ 输入或粘贴中文、英文…                                       │
│                                                              │
│ Enter 翻译 · Shift+Enter 换行                               │
├─────────────────────── [⇅] ────────────────────────────────┤
│ [简体中文 ▾]                                      [复制]  │
│                                                              │
│ 翻译结果在这里显示，可选择和复制                              │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ [齿轮]  deepseek-flash  [通用 ▾]                  翻译       │
└──────────────────────────────────────────────────────────────┘
```

- 保留 shell 标题栏、返回与分离操作；插件不重复造标题栏。
- 按用户参考图调整为一个上下分区的内容框：源语言和目标语言分别位于区域顶部，译文区域使用主题的弱背景色；中央圆形按钮交换上下文本，其他分隔线区域仍可拖动。不重复显示「原文／译文」大标题。
- 原文为可编辑多行文本，译文为可选择的只读多行文本，默认换行、各自滚动。正文使用界面字体；首版展示并复制 Markdown 源文本，不自动解析成富文本或加载远程图片。
- 技术文档中的代码围栏、链接等在文本中保留，不提供源码执行、链接预取或自动打开外部资源。
- 「翻译」是明确的主要提交动作；复制、清空、设置使用共享图标按钮和悬浮提示，并保留无障碍名称。设置齿轮位于底栏，复制位于译文区域右上角。
- 译文优先占据剩余空间。状态放在译文附近；不弹出每次完成的成功 toast。
- 当前框架默认启动器约 800×600，分离窗口约 960×680。建议最小可用窗口按 640×520 验证，同时验证字体 12–20 的缩放。尺寸属于窗口约束，内部控件沿用 rem 和主题 token。
- 窄窗口允许方向栏折行，低频模型信息可收进设置入口；翻译和停止保持可见。工具栏不水平滚出窗口。

### 翻译方向

内部方向仍只有「自动」「英文 → 中文」「中文 → 英文」。源语言选择「自动检测／英语／简体中文」，目标语言选择「简体中文／英语」；手动选择目标语言会确定相应的中英方向。中央按钮交换原文和译文，停止当前请求并使旧结果失效，不单独反转语言选择；自动模式按交换后的新原文重新识别。中文目标默认简体中文；英文目标使用自然、通用的英文，不增加地区下拉框。

自动模式在本地判断正文的主语言，显示实际选择，例如「自动：英 → 中」。判断应忽略代码块、行内代码和 URL 对正文统计的干扰；少量英文技术名词不应把中文段落判为英文。具体阈值用中英混排样例校准，不把本地启发式显示为权威识别结果。

只有符号、代码，或中英比例难以判断时，显示「请选择翻译方向」，让用户明确选择后再发送。用户手动选择后保持该方向，不被后续输入自动覆盖。

更改语言选择只改变下一次翻译目标。中央交换按钮只承担交换上下文本的操作，交换后保留原文撤销能力。模型信息与通用／技术场景选择放到底部工具栏，不占据译文区。

### 翻译场景

| 场景 | 翻译要求 |
| --- | --- |
| 通用（默认） | 自然、忠实，保留语气，不额外解释、总结或改写事实 |
| 技术 | 准确和一致优先，保留 API / 类型 / 变量 / 命令 / 路径 / URL；不翻译代码块及行内代码，翻译周围正文 |

两种场景都应保留段落、列表、Markdown 标记、链接目标和占位符。技术模式不是另一套模型，也不自动切换 endpoint。原文中的“忽略以上要求”等文字仍作为待翻译内容，不能成为调用工具或泄露配置的指令。

这些约束首先由提示词表达。模型不构成逐字保真保证：代码、链接及占位符的保留需要用真实样例验收，不在设计阶段宣称已经保证。

## 6. 状态、编辑与恢复

| 状态 / 事件 | 显示和行为 |
| --- | --- |
| 空原文 | 显示输入提示，翻译与复制禁用，原因由邻近提示说明 |
| 未配置 Key | 原文仍可编辑；译文区提供「配置 DeepSeek…」；不靠日志提示用户 |
| 等待首个片段 | 显示「正在连接…」和停止按钮，不显示虚构进度百分比 |
| 正在翻译 | 逐步更新译文，保持方向、原文和场景这一份请求快照；不允许重复发送 |
| 完成 | 保留译文，启用复制；显示正常完成状态 |
| 用户停止 | 保留已收到文本，明确标记「已停止，译文不完整」；允许复制已生成文本 |
| 网络中断 | 保留部分结果，显示「连接中断，译文不完整」和重试；不自动拼接两个请求的结果 |
| 输出上限 | `finish_reason = length` 等截断原因显示「译文未完整生成，请分段翻译」；不能显示完成 |
| 修改原文 / 方向 / 场景 | 取消正在进行的请求，保留旧结果并标记「内容已修改，请重新翻译」；迟到片段不覆盖新状态 |
| 更换连接配置或 Key | 取消正在进行的请求，保留并标记旧结果；下一次使用新配置，不在请求途中更换 Key 或地址 |
| 清空 | 停止请求并清空两区，输入组件保留正常撤销能力；不弹确认框 |
| 隐藏弹窗 / 返回启动器 | 会话实体仍在时继续用户已发起的翻译，重新打开看到当前结果；不会重复发送 |
| 分离窗口 | 移动同一个视图，保留输入、请求和结果，不另发请求 |
| 实体释放 / 退出应用 | 取消请求并释放资源；已发送的服务端请求不承诺撤销计费 |

第一次请求失败前不丢弃已有结果：开始时可标记旧结果，收到新请求首个有效片段后再替换。复制按钮文案必须区分当前译文、旧译文和未完成的译文，避免误把过期结果当成新结果。

首版只保留本次进程内会话，不增加磁盘翻译历史。已有 JSON / Diff 的草稿自动保存机制不自动套用到翻译文本。

### 错误反馈

| 错误 | 用户可见说明与下一步 |
| --- | --- |
| 401 | Key 无效或已失效，提供「检查配置…」 |
| 402 | 账户余额不足；官方连接可提供官方充值入口，自定义连接不错误指向 DeepSeek 充值 |
| 404 / 405 | 检查完整接口地址与模型名；不推断一定是 Key 错误 |
| 400 / 422 | 检查模型及请求参数兼容性，显示经过脱敏和长度限制的说明 |
| 429 | 请求过于频繁，等待后手动重试；可展示有效的 Retry-After |
| 5xx | 服务暂不可用，保留内容，提供重试 |
| DNS / TLS / 超时 / 离线 | 给出对应连接说明；不关闭证书验证来“修复”连接 |
| 无内容 / 无法解析的响应 | 明确提示没有收到有效译文；空正文不计为成功 |

HTTP 状态含义参考 [DeepSeek Error Codes](https://api-docs.deepseek.com/quick_start/error_codes/)。自定义服务的错误体可能不同，最终以实际响应为准。

首版不自动重试生成请求，避免用户取消后仍重试，以及重复费用。超时建议起点：连接 10 秒、无新译文 60 秒、单次总时长 180 秒，作为内部常量，通过实测后调整，不堆进普通用户设置页。

## 7. 设置与凭据

设置侧栏新增「AI 翻译」。插件的「设置…」与缺失 Key 引导应直达这一页；目前 `Shell::open_settings` 无目标页参数，需要增加小范围的页定位能力，而不是打开后要求用户再次找菜单。

```text
设置 / AI 翻译

连接
接口地址   [ https://api.deepseek.com/chat/completions      ]
           填写完整的 Chat Completions 请求地址，包含路径
模型名称   [ deepseek-flash                                ]
                                  恢复官方默认   保存连接

凭据
当前来源   环境变量 DEEPSEEK_API_KEY / 已保存 Key / 未配置
API Key    [ 输入新的 API Key                         显示 ]
                                         保存 Key   移除已保存 Key
           Key 保存到系统凭据存储，不写入普通设置文件

检查连接   [ 测试连接 ]    尚未测试
           使用固定短文本，会产生少量模型调用费用
```

### 明确 endpoint 的含义

- `endpoint` 是完整请求 URL，默认 `https://api.deepseek.com/chat/completions`。
- 不猜测或追加 `/v1`、`/chat/completions`。示例和校验文案明确区分完整 URL 与 Base URL。
- 用户可填写代理完整路径；自定义服务必须支持所选 DeepSeek 模型的 Chat Completions 接口。这里不等价于支持所有 OpenAI 或 Anthropic 服务。
- 要求 HTTPS；本机环回地址可允许 HTTP。拒绝 URL 内嵌账号密码，不跟随带凭据请求的重定向。
- 连接字段编辑时为草稿，点击「保存连接」完成校验并生效；无效内容不覆盖正在使用的配置。测试只针对已保存的连接，未保存时说明需先保存。
- 恢复官方默认只作用于 endpoint 和 model，不删除其他地址的 Key，不修改原文、译文或主题。

### Key 的优先级与存放

1. 当前 endpoint 对应、用户通过设置保存的非空 Key。
2. rtools 进程中非空的 `DEEPSEEK_API_KEY`。
3. 都没有则进入未配置状态。

保存 Key 与保存连接是两个明确操作，不在每次键入时写 Keychain；使用 rtools 命名空间和规范化 endpoint 隔离凭据，避免修改地址后静默复用另一个地址的已保存 Key。

界面显示来源，默认遮盖输入；不回显环境变量中的完整 Key。输入框用于替换 Key，留空表示不替换；删除已有 Key 必须使用明确的「移除已保存 Key」。移除后若存在环境变量，立即显示回退后的来源。已保存 Key 返回 401 时不静默换用环境变量继续请求。

自定义地址页面应明确显示将连接的主机，以及该地址会接收 Key 与原文。环境变量只从当前进程读取；终端设置了变量而 GUI 进程没继承时，应显示「未检测到环境变量」，不读取 shell 配置文件或伪装成已配置。

如果平台凭据存储不可用或访问被拒绝，保存操作给出错误，仍可使用环境变量；不自动降级为明文保存。macOS Keychain API 已核对，其他平台的可用性需实机验证。

### 测试连接

显式发送一次固定、极短的请求，验证地址、鉴权、模型以及内容响应；不读取或发送用户当前原文，不以 `/models` 可访问就宣称翻译可用。测试按钮有进行中、成功、失败状态。配置变更后清除旧的测试成功状态。

普通偏好继续保存在 `settings.toml`，示意如下；其中不包含 Key：

```toml
[translate]
endpoint = "https://api.deepseek.com/chat/completions"
model = "deepseek-flash"
direction = "auto"       # auto / en-zh / zh-en
scenario = "general"     # general / technical
```

## 8. 键盘、主题与无障碍

- 原文框 `Enter` 发起翻译，`Shift Enter` 换行；保留 `⌘ Enter` / `Ctrl Enter`。复用 Textarea 的 `submit_on_enter` 与输入事件处理，中文输入法组合输入不能误提交。
- Esc 优先关闭当前下拉框；无覆盖层且翻译进行中时停止，空闲时交还既有返回行为。
- 原文和译文保留标准选择、复制及原文撤销；全局复制整段译文可使用 `⌘ Shift C` / `Ctrl Shift C`，不抢占 `⌘ C` 的选区复制。
- 复用既有分离窗口快捷键；图标按钮有可访问名称，当前焦点和禁用状态可辨认。
- Tab 顺序与视觉顺序一致；配置页返回时保留翻译输入，避免焦点落到隐藏的启动器窗口。
- 原文、译文、错误及工具栏均使用现有主题语义色；验证 Default Light / Dark、Ayu 等自定义主题和字体缩放。
- 结果更新不抢焦点；用户滚动阅读前文时不强制滚到底部。流式状态公告不逐 token 播报。

## 9. 实现边界与效率要求

保持现有按插件组织的结构，建议放入 `plugins/translate/`，由插件入口、核心类型 / 请求构造、DeepSeek 客户端和视图组成。具体文件数量由实现规模决定，不为每个小函数创建类型。

- `TranslateView` 拥有原文、译文、方向、场景、状态、当前任务及请求版本号；异步任务通过弱实体回写，不持有跨 await 的 Window / Context 引用。
- `DeepSeekClient` 拥有可复用 HTTP 客户端；每次请求使用独立的连接、Key 和文本快照。所有网络和耗时解析离开 UI 线程。
- 配置校验可使用 `TryFrom`；错误使用有意义的 `thiserror` 变体，视图负责转成用户可理解的文案。
- 不增加通用 Provider trait、Agent 会话、工具调用或消息数据库。
- SSE 按完整事件解析，不能把一次网络读取当成一个 JSON；覆盖 UTF-8 分片、空行、注释心跳、空 choices、结束标记及非 JSON 错误体。
- 官方连接显式关闭思考。自定义 endpoint 优先使用基础 Chat Completions 字段，不无条件发送 DeepSeek 私有扩展；如果其模型默认输出思考内容，只提取译文正文，不显示或持久化推理内容，等待时间由该服务决定。
- 以小批次增量更新 UI（例如 30–50 ms 一次），不要每个 token 都复制整份结果、重新设置整个编辑器或刷新全局主题。
- 内部设置请求、事件与结果大小上限。建议首版输入上限 20,000 个 Unicode 字符，超过时保留原文并提示分段，不静默截断；输出预算及超时使用技术长段落样例验证。长文自动分块与合并暂不加入。
- 日志记录请求开始、完成、停止、失败，以及请求编号、方向、字符数、目标主机、耗时和状态码；不记录 Key、Authorization、原文、译文或原始错误响应。遵守项目的正文格式 tracing 规则。

## 10. 验收与未验证部分

以下为验收范围；实现和已完成的验证记录见 [实施计划](../plans/2026-11-16-ai-translate.md)。未列入实测记录的项目不能视为已验证：

1. 英文日常文本转中文、中文日常文本转英文，手动方向优先于自动判断。
2. 中文正文混合英文 API 名称，英文正文含少量中文引用，代码占主要篇幅及只有符号的输入。
3. Markdown 标题、列表、链接、代码围栏、行内代码、变量占位符保留；技术模式术语一致，通用模式语气自然。
4. Key 优先级、空变量、GUI 未继承变量、凭据保存失败、修改 endpoint 后的凭据隔离。
5. 默认官方地址、自定义完整路径、尾斜杠、无效 URL、HTTPS 和本机 HTTP 校验，不重复拼接路径。
6. SSE 分片、无输出、停止、超时、输出截断、旧请求迟到，以及所有明确的错误状态。
7. 输入修改、返回、隐藏、重新唤起、分离窗口和关闭窗口期间的生命周期。
8. 键盘操作、输入法组合输入、窗口最小尺寸、缩放、长文滚动、浅色 / 深色 / 自定义主题。
